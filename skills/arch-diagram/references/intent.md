# 目标卡（intent）

本 Skill 的生产者已确认（2026-11-26）。评测用例从这张卡推出；改目标先改这里。

## 给谁用

黑湖的产品经理、FDE、解决方案架构师：在需求讨论、方案设计、对内对外沟通时，要把讨论结论画成架构图并持续维护的人。

## 解决什么问题、什么时候触发

- 把对话里的讨论结论凝练成**可编辑**的 draw.io 图：系统 / Agent 架构、分层图、业务流程、泳道图、模块关系图、时序。
- 随讨论多轮增量修改：只局部改，带版本快照、逐轮差异、变化高亮、回退。
- 交付：导出 PNG / SVG / PDF；**可选**同步到飞书云文档里的原生画板，并把团队成员在飞书或 draw.io 上的人工改动合回来，作为高优先级意图用于下一轮。
- 触发说法：画 / 更新架构图、系统图、流程图、泳道图；把刚才的讨论画成图；图里加 X、把 Y 改成 Z、删掉 W；这轮改了什么、回到上一版；导出 PNG；放进飞书 / 同步飞书；提到 draw.io、.drawio。

## 不做什么

- 不画数据图表（柱状图、饼图、折线图等），不做 UI 原型和页面设计稿。
- 不编辑飞书文档正文：只在文档末尾追加、覆盖本工具建的画板，文档其他内容不动（由别的 Skill 负责）。
- 不做纯 Mermaid / PlantUML 代码问答。
- 不替用户输入或保存飞书密钥、token。

## 怎样算成功（可核对）

1. 每轮 `diagram.py check` 退出码 0（结构校验 + 图与清单一致）。
2. 每轮都打开预览 PNG 看过，并在回复里给出预览和一句话变化摘要。
3. 迭代时未变化的节点坐标不变，只做局部修改；每轮有快照，`diff` 能说出改了什么。
4. 同步飞书时，画板的形状、文字、连线与 draw.io 一致；飞书侧被改过时不覆盖，先合回并告知用户。
5. 人工改动零丢失：合回后保留，写进清单的 `by` / `intent`，与新需求冲突时说明冲突并请用户裁决。

## 分发范围

`team`：黑湖内部，跨人、跨项目使用。飞书同步依赖团队的飞书企业版租户，属于可选功能。
