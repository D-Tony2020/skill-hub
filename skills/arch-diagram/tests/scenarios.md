## 通用通过标准（每个场景都要满足）

- `diagram.py check` 退出码 0：validate 0 error，清单一致性 0 error
- 预览 PNG 人眼检查：无箭头压字、无标签重叠、无线穿节点、无大面积叠线
- 交付物齐全：`<slug>.drawio` `<slug>.png` `<slug>.drawio.svg`，history 有本轮快照
- 回复符合规范：一句话改动 + 预览 + 路径

## 场景

### S1 新建 · Agent 架构
讨论：「做一个缺料齐套 Agent：业务员在飞书里发起查询，Agent 先查 ERP 的 BOM 和库存算齐套率，缺料的去 WMS 查在途，
再查采购单交期；算完把齐套报告推回飞书。Agent 要有记忆，记住每个物料的历史催料记录。」
期望：actor + agent + 3 外部系统(ERP/WMS/采购) + 记忆 + 飞书；关系 ≥7 条。

### S2 增量修改
在 S1 基础上：「齐套计算和催料拆开，催料单独一个 Agent，由它给供应商发催料消息；采购单交期改成从 SRM 查，不走 ERP 了；
记忆改成两个 Agent 共享。」
期望：新增 催料Agent/供应商/SRM；删除 Agent→采购(ERP) 关系；未变节点 0 漂移；diff 输出与改动一致。

### S3 用户手动修改后再迭代
模拟用户在 draw.io 里：移动 2 个节点、把一个节点改成红色、加一条备注文本，并以**压缩格式**保存。
然后要求：「给催料 Agent 加一个人工审批环节」。
期望：读到压缩文件；用户的移动/颜色/备注全部保留；只新增审批相关元素。

### S4 分层架构
「黑湖智能制造平台分四层：接入层（飞书、企微、Web）、应用层（齐套Agent、催料Agent、排产Agent）、
能力层（LLM网关、知识库、工具注册中心）、数据层（ERP、MES、WMS）。应用层通过能力层访问数据层。」
期望：4 个容器，子节点 parent 正确；跨层关系不穿越无关节点。

### S5 跨角色泳道流程
「缺料催料流程：计划员发现缺料 → 系统判断是否有在途：有在途则跟踪到货；无在途则采购员确认是否紧急，
紧急则电话催料，不紧急则系统发催料单给供应商 → 供应商回复交期 → 计划员更新排产。」
期望：泳道 计划员/系统/采购员/供应商；2 个判断节点且分支标注 是/否；流程无断链。

### S6 大图自动布局
22 个节点的微服务依赖图（给定清单）。
期望：走 autolayout 路线；0 节点重叠；交叉数可接受；可读。

### S7 待定项 + 图例
在 S4 基础上：「排产 Agent 先不确定要不要做，标成待定；知识库是用飞书知识库还是自建也没定。」
期望：两处以待定样式呈现（与正式节点可区分）；图例自动生成且只包含图中用到的类型。

### S8 版本对比 / 回退 / 变更高亮
基于 S1→S2→S3 的历史：输出 r01→r03 diff；生成 r03 相对 r02 的变更高亮图；回退到 r02 再前进。
期望：diff 准确；高亮图只标出变化元素且不改动源文件；回退前自动快照、可再恢复。

### S9 多页面
在 S4 基础上加第 2 页「齐套 Agent 内部结构」（规划器、工具调用、结果校验、记忆读写）。
期望：两页都通过检查；可按页导出。

### S10 飞书交付
对 S2 产物执行交付：.drawio（用于画板导入）、PNG、Mermaid 降级；执行 `sync`。
期望：飞书未配置时给出明确提示与手动导入步骤，退出码非 0 但不报错崩溃；Mermaid 可渲染。

### S11 健壮性
路径含中文与空格（`arch-diagrams\测试 图`）；标签含 `&` `<` `>` `"` 和 40 字长标签。
期望：所有命令正常；导出图文字不溢出、不乱码。
