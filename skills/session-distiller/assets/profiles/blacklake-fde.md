# 长期目标画像：黑湖科技 FDE（Dean）

> 预置画像。`sd init --profile blacklake-fde` 会把它复制到 `~/.session-distiller/profile.md`，之后改本机那份即可；
> 想让改动跟着你走到别的机器，就改源码仓库里的这份并提 PR。

## 我是谁

- 黑湖科技（Blacklake，工业数智化软件）的 FDE（Forward Deployed Engineer）。
- 背景：前大厂 AI 产品事业部负责人，软件工程科班；长期做 To B 企业数智化与 AI 赋能。
- 工作方式：分布式使用多个 Agent，以 session 为单位推进一个个客户项目（需求 → Agent 产品 → 部署 → 现场）。

## 沉淀范围

凡是**产研、部署、现场**环节里可能复用的东西都在范围内：

- 产研：需求拆解、方案设计、Agent 产品开发、评测、工程管线（仓库、分支、CI、发布、内网研发链路）。
- 部署：环境搭建、私有化与内网部署、数据对接（ERP/MES/WMS、Excel、飞书等）、上线检查、运维排障。
- 现场：客户访谈与需求确认、演示、培训、验收、问题收集与回传。

## 沉淀重点

1. **工程化**：工程管线上反复出现的事情是主体，但不止于工程化；方法论、业务知识同样算。
2. **资产分层**：每个候选都要判断它属于哪一层（见 rubric 的"三层资产"）。
   - 项目资产：只对这个客户、这个项目成立，留在项目里，不往外提。
   - 行业资产：对制造业（某类工厂、某个业务域，如生产、排程、采购、质检、仓储、财务）普遍成立。
   - 基座：跨行业成立的 Agent 能力、工程管线、交互范式与工具。
3. **交互流程与工具**：在某个业务场景下"我如何与 Agent 协作"的方式（先给什么材料、在哪些节点确认、产出什么中间物、用什么工具），下一个场景大概率沿用。识别到就沉淀，连同流程中用到的工具一起。

## 展望

把沉淀物蒸馏成**不同层级的 skill 或记忆文件**，在 Skill Hub 里拼装：基座 skill 被行业 skill 复用，行业 skill 组合成项目方案；能力可以重新拆分或合并。所以每个候选要写清楚它建立在哪些已有 skill 之上（builds_on）。

## 高价值领域（命中加分）

- 业务域：生产执行/MES、APS 排程、采购与供应商协同、销售订单、质检/QMS、仓储物流/WMS、成本与财务、单据识别与录入。
- 技术域：Agent 编排与多 Agent 协作、skill 工程（生产、评测、发布、运维）、ERP/MES 数据对接、飞书生态、内网 GitLab 研发链路、私有化部署。
- 交付域：售前方案、PoC、需求调研模板、实施 SOP、客户培训、验收清单。

## 偏好与约束

- 形态偏好：规则 + 可执行脚本（可复现、可测试）；其次是记忆文件（短规则）和方法论参考。
- 必须跨环境：Windows 开发机、内网 Mac、云端会话都能用；不依赖某台机器的私有状态。
- 合规：客户名、内部地址、凭据一律不进入沉淀物（客户名写进 `redact.txt`）。

## 不要提炼的东西

- 某个客户的一次性数据或定制计算（属于项目资产，留在项目内）。
- Agent 本来就会的通用编程常识；已有成熟开源方案、无需二次封装的通用工具。
- 纯个人琐事。
