# skill-feedback 目标卡

## 一句话目标

当使用者在用某个 Skill 时遇到问题，它会定位版本和源码仓库、区分 Skill 问题与环境问题、写出脱敏的最小复现，并在用户确认后生成预填的 issue 链接，让问题回到作者手里时可以直接处理。（基建清单「5 反馈」）

## 给谁用

- 角色：使用者、作者
- 使用频率：遇到问题时

## 触发说法

1. skill-qa 有个误报，帮我反馈给作者
2. 这个排产 skill 交期老算错，帮我整理一下提给维护的人
3. 我说帮我画架构图的时候 arch-diagram 没出来，这个跟谁说
4. 给 hub-starter 提个建议

## 不做什么

1. "帮我把 qa.mjs 的规则改掉" → 交给 skill-creator（改源码）
2. "客户反馈 MES 卡顿，写个问题单" → 交给 Claude 直接做（不是 Skill 的问题）
3. "npm install 报错怎么办" → 交给 Claude 直接排查
4. "把修好的版本发布到 Hub" → 交给 skill-hub-ops

## 成功标准

1. 草稿写明版本、安装来源、期望、实际、复现
2. 草稿不含客户名、密钥、内网地址、个人目录
3. 用户看过草稿后才生成链接或提交
4. 环境问题和已修复的问题不产生 issue
5. 安全问题不发公开 issue

## 输入与输出

- 输入：用户描述、对话记录、已安装的 Skill 目录
- 输出：issue 草稿和预填链接

## 环境前提

- Node 18+；提交需要用户的 GitHub 账号

## 与已有 Skill 的关系

- Hub 查重：无
- 仓库查重：基建清单原计划并入 skill-hub-ops；拆出来是因为使用者不需要仓库权限，也不该装运维手册

## 未决问题

- 负责人确认本目标卡，以及"独立成 Skill、不并入 skill-hub-ops"的调整
