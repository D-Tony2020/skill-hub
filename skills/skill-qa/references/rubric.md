# 评分表（G8）

5 项，每项 0–2 分，总分 ≥ 8 且"安全"不为 0 才通过。"安全"打 0 分，结论直接是"不收录"。每项都要写依据，引用 SKILL.md 原文或文件行号。拿不准就打低分并写明原因，不要为了让结论变成"可分发"而抬分。

维度参考了 Tessl 的 8 项（简洁度、可执行性、流程清晰度、渐进加载、具体性、完整性、触发词质量、与其他 Skill 的冲突），合并成下面 5 项。

## 触发（trigger）

description 能不能让该用的说法触发、不该用的说法不触发。

- 2：写清了做什么、用户会怎么说（列出真实说法）、不用于什么；与 Hub 里已有的 Skill 没有冲突。
- 1：缺其中一样；或者用词太泛，容易和别的 Skill 抢。
- 0：看不出什么时候该用。

## 可执行（actionable）

Agent 只看 SKILL.md，能不能知道第一步做什么、何时读哪份参考。

- 2：第一屏写清执行环境和核心规则；步骤有顺序；每份 references 都写了什么时候读；正文不超过 500 行。
- 1：能做下去，但要靠猜（例如步骤顺序不明、参考文档没说什么时候读）。
- 0：只有概念介绍，没有可执行的步骤。

## 确定性（deterministic）

需要精确的步骤是否写成了脚本，脚本是否有测试。

- 2：拼命令、改文件、调接口这类步骤都在 scripts/ 里，而且有测试；SKILL.md 只负责调度和判断。
- 1：有脚本但没有测试，或者还有关键步骤要 Agent 临场拼命令。
- 0：全靠 Agent 临场发挥，结果每次不一样。纯写作类 Skill 没有可脚本化的步骤时，按 1 计，并写明原因。

## 安全（safety）

- 2：不可逆操作（删除、推送、发消息、改生产、提权）前都有确认；没有密钥和内网信息；需要提权的地方写清了理由；扫描告警都已处置。
- 1：有不可逆操作但确认写得不够明确；或者提权理由不完整。
- 0：会在没有确认的情况下做不可逆操作；或者含密钥；或者有"下载即执行"之类的真漏洞没修。

## 可移植（portable）

换一台机器、换一种安装方式（插件市场、SkillHub、手动拷贝），还能不能用。

- 2：路径从 SKILL.md 所在目录算；依赖都写进了 requires；只支持某个系统时在开头写明；用户数据放在用户目录，升级不会丢。
- 1：有一处写死路径或没声明的依赖，但容易修。
- 0：只能在作者的机器上跑。

## 写进 review.json 的格式

```json
"rubric": {
  "trigger": { "score": 2, "why": "description 列了 5 种说法，并写明不用于从零写 Skill" },
  "actionable": { "score": 2, "why": "..." },
  "deterministic": { "score": 1, "why": "..." },
  "safety": { "score": 2, "why": "..." },
  "portable": { "score": 2, "why": "..." }
}
```
